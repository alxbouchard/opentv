# Plan — MVP « Pour toi » (OpenTV v23, pont NanoPi)

Statut : implémenté (voir `scripts/nanopi/FORYOU.md`). Ce plan fixe les choix avant le code.

## Objectif

Une tuile OpenTV « Pour toi » (appli externe NanoPi, comme « Films ») ouvre sur HDMI 1 une sélection
personnalisée du **même catalogue accepté**, avec actions à la télécommande (Regarder, J'aime, Pas pour moi,
Déjà vu, À voir plus tard, Pas ce soir), un historique local durable et une CLI JSON pour Muse/Hermit.

## Décisions

1. **Réutiliser la pile Films** : même service `opentv-bridge`, même contrat API v1 (clé d'appli `pourtoi`
   ajoutée à `APPS`), même session unique, même kiosque, même lecteur (`_open_item`, routage site_id,
   assistance de lecture). Seuls changent : l'URL locale de la vue (`/ui/pourtoi/`) et la navigation dans
   l'état `catalogue` (rangées + panneau d'actions). Contrat TV inchangé (états `starting|catalogue|player|dashboard`).
2. **Module dédié** `scripts/nanopi/opentv_foryou.py` (stdlib) : stockage SQLite, moteur, navigation, CLI.
   `opentv_bridge.py` le charge par chemin explicite (compatible `python3 -I`) et ne garde que des crochets fins.
3. **Identifiant stable** `<espace>/<site_id>` (ex. `films/17397`) : `espace` = `FORYOU_SOURCE_ID` (défaut
   `films`), espace de noms logique validé strictement, indépendant du domaine, de `SITE_ROOT`, du préfixe, du
   jeton et des routes (un changement d'ancre fakrov→wadrox n'orpheline rien) ; `site_id` = identifiant
   interne stable du site.
   Les éléments sans `site_id` ne sont ni recommandés ni annotables.
4. **Stockage** `STATE_DIR/foryou.sqlite3` (0600, dossier 0700, hors Git), `PRAGMA user_version` = schéma 1 :
   `prefs` (opinion like|dislike exclusive, seen, watchlist, snooze « pas ce soir » avec échéance),
   `events` (journal des changements, seulement si l'état change → idempotent), `signals` (`opened` :
   film ouvert, **jamais** interprété comme vu), `catalogue_seen` + `snapshots` (première apparition d'un
   identifiant dans un catalogue accepté ; le 1er instantané est la référence, jamais « nouveau »).
   Bornes : 5000 événements/signaux (élagage des plus anciens).
5. **Moteur déterministe** (fonction pure, horloge injectée) : candidats = catalogue accepté avec site_id,
   moins vus, « pas pour moi », « pas ce soir » actifs, et site_id connus absents de la table de routage.
   Tri : goût appris (poids de genres : +1 J'aime, −1 Pas pour moi, +0,5 liste) → qualité (palier de confiance
   par nombre de votes, puis note, puis votes ; IMDb sinon TMDb apparié, jamais de moyenne) → nouveauté
   (ajout au catalogue détecté par instantanés, sinon année de sortie récente) → titre/identifiant ;
   puis diversité (pas deux fois de suite le même genre principal quand une alternative existe).
   Aucune note inventée : les explications citent les valeurs brutes de chaque fournisseur.
6. **Rangées** (≤ 12 éléments, chaque film une seule fois) : « Le choix de ce soir », « À voir plus tard »,
   « Parce que tu as aimé « X » » (si un J'aime existe), « Nouveautés disponibles », « Les mieux notés que tu
   n'as pas vus », « Autres suggestions ». Profil vide = qualité + nouveauté, explication honnête.
7. **UI kiosque** `opentv_foryou_ui.html` : ES5, sans grid/gap/inset/flou, affiches seulement autour de la
   rangée courante, barre d'actions toujours visible. OK sur un film → panneau d'actions, « Regarder » en
   premier et présélectionné ; J'aime/Pas pour moi/Déjà vu/À voir plus tard/Pas ce soir sont des bascules
   (rappuyer = annuler) ; le film reste en place pendant la session (pas de disparition surprise).
8. **Agents** : CLI locale `python3 -I ~/opentv-bridge/opentv_foryou.py status|recommend|search|feedback|history`,
   JSON trié, entrées typées et bornées, codes de sortie, aucune URL (nettoyage global de toute chaîne
   sortante ; requête ressemblant à une URL refusée). Pas de nouveau port ; `ALLOW_IPS` inchangé.
9. **OpenTV** : entrée `pourtoi` dans `NOVA_EXTERNAL` (après Films), icône étoile, BUILD v23 + `?b=23`.
   Service Tizen inchangé (SVC_VERSION 17).
10. **Installation** : `install-bridge.sh` copie le module + la vue ; aucun paquet hôte ; la base est créée
    à la première utilisation sous `STATE_DIR`.
